# Research protocol (V1.5, spec §11)

Code: `bot/research/protocol.py`. Commands: `python -m bot research run|report|trials`. The protocol is the only way a
V1.5 module gets a number attached to it; a backtest run outside it is not evidence of anything.

## Cuts (fixed, never moved)

| Cut | Period | Role |
|---|---|---|
| A | 2016-01 – 2018-12 | exploration: look, do not report |
| B | 2019-01 – 2021-12 | development: parameter surfaces |
| C | 2022-01 – 2023-12 | validation: default parameters only, bootstrap, stress, regimes |
| D | 2024-01 – 2026-06 | holdout, **sealed** |

`research run --cut D` refuses unless `--unseal --reason "<text>"` is given. Every unsealing appends a row with the UTC
time, module, parameter hash, code hash (git HEAD + SHA-256 of the strategy/engine/spine sources) and config hash to
`research/UNSEAL_LOG.md`. Unseal once per module, at the end, and only to decide promotion.

## Trial registry

Every backtest run through `run_trial` (surface points, validation, stress runs) appends a row to `research/trials.sqlite`
(module, cut, parameter hash and values, code hash, data hash, stress, Sharpe, return, trades, all metrics). Reports read
the count of distinct parameter sets on the same module and cut and deflate the Sharpe ratio accordingly (Bailey and
López de Prado's deflated Sharpe: expected maximum Sharpe under N trials given the variance of trial Sharpes, then the
probabilistic Sharpe against that benchmark, adjusted for skew and kurtosis). Deleting the registry to reset the count
is cheating; the file is operator data and is not committed.

## Declared surfaces (no hand-chosen grids)

| Module | Surface | Default (used on C and D) |
|---|---|---|
| M1 | target_vol {0.08, 0.10, 0.12} × cap {0.5, 0.6} | 0.10 / 0.6 |
| M2 | k {0.25, 0.5, 0.75, 1.0} × agreement {off, on} × entry {15:15, 15:30, 15:45} | 0.5 / off / 15:30 |
| M3 | n_bottom {2, 3, 5} × hold_sessions {3, 5, 7} | 3 / 5 |

The `relvol_1515 > 1` filter for M2 is a declared variant that needs lagged SIP volume; run it as
`research run --module M2 --cut B --params relvol_filter=true` and it lands in the registry like any other point.
Validation on C always uses the pre-declared default, never the B-best point.

## Required report per module (`research/RESULTS_V1_5.md`, generated by `research report`)

1. Parameter surface on B: every point, median Sharpe, best point, share of the best point's neighbours within 30% of it.
2. Validation on C with the default parameters: Sharpe, return, drawdown, trades, net expectancy per trade with a
   circular block-bootstrap 90% interval (block 5, 2000 resamples).
3. Cost stress on C: 2× spread, 2× slippage, 1-bar delay, 10% dropped signals, adverse 2 bps on 20% of fills.
4. Regime table on C with **causal** labels: trend = sign of the trailing 126-day benchmark return; vol = trailing
   21-day realised vol above the 75th percentile of its own past 252 days (shifted by one day). The previous harness
   compared with the full-sample quantile, which leaked the future; fixed in this phase.
5. Overnight / intraday attribution.
6. Deflated Sharpe from the registry count.
7. Pass/fail against the fixed criteria:
   - surface median Sharpe > 0 and ≥ 70% of neighbours within 30% of the best;
   - C bootstrap lower bound of net expectancy > 0 (and at least 10 trades);
   - every stress leaves net profit positive and within 60% of base;
   - no regime with Sharpe < −0.5 covering > 25% of the sample;
   - attribution consistent with the mechanism (M2 intraday, M1/M3 overnight).

All runs go through the V1.5 spine (SimBroker fills, RiskEngine admission, Allocator, OrderManager) with the production
throttle disabled, on the paper policy. Fractional-account simulation: `--fractional`.

## Promotion

`research/PROMOTIONS.md` gets a line `## <MODULE> promoted <YYYY-MM-DD> ...` only when the module passed B and C, and
then D once (unsealed, logged). `RiskPolicy.load(..., require_promotions=True)` — the live path — refuses a policy that
allows a V1.5 module without such a line. The two V1 baselines are exempt (their gate is FINAL_REPORT.md).

## Data

The protocol reads the local cache only and never fetches. Daily cuts need 260 sessions of warm-up before the cut
(`python -m bot data fetch --symbol SPY --start 2014-01-01`); M2 needs 1-minute bars covering the cut plus 45 days
(`python -m bot data fetch --timeframe 1m ...`); M3 needs Tier 3 from `config/universe.yaml` (`universe build`).
When data is missing the report says NOT EVALUATED with the reason; it never substitutes proxies.
